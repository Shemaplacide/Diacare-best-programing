# Deploying DiaCare (free plans)

| Part | Host | Plan | URL |
|------|------|------|-----|
| React frontend (`DiaCareFrontend`) | Vercel | Hobby | https://diacare-one.vercel.app |
| Spring Boot API (`DiaCare`, Docker) | Render | Free web service | https://diacare-api.onrender.com/api/v1 |
| Health check | Render | | https://diacare-api.onrender.com/api/v1/health |
| PostgreSQL 18 | Neon | Free (project `diacare-demo`, Frankfurt) | private |

All three plans are free with no card required. When a limit is reached they suspend or
throttle instead of billing (Render with no card on file, Neon Free, Vercel Hobby).

## Free-plan limits that affect the demo

- **Render Free:** 512 MB RAM, 750 instance hours a month per workspace (shared by every
  free service in it). The service sleeps after 15 minutes without HTTP traffic and takes
  about a minute to wake. No persistent disk, and outbound SMTP ports 25/465/587 are blocked.
- **Neon Free:** 1 GB storage and 100 CU-hours a month per project; compute scales to
  zero after 5 minutes idle. 6 hours of point-in-time history.
- **Vercel Hobby:** personal, non-commercial use only; hard usage caps.

While the API sleeps, the frontend pings `/health` on load and shows
"Connecting to the DiaCare server…" for any request slower than four seconds. Forms keep
their entries if the server cannot be reached.

## Environment variables

Set these in Render → `diacare-api` → Environment. Values below are placeholders; real
values live only in the provider dashboards.

| Variable | Example | Notes |
|----------|---------|-------|
| `SPRING_DATASOURCE_URL` | `jdbc:postgresql://<endpoint>-pooler.<region>.aws.neon.tech/<db>?sslmode=require&channelBinding=require` | Neon → Connect → copy the host and database into this JDBC form (no user or password in the URL) |
| `SPRING_DATASOURCE_USERNAME` | `<neon role>` | |
| `SPRING_DATASOURCE_PASSWORD` | `<neon password>` | |
| `JWT_SECRET` | `<at least 32 random characters>` | Generated by the Blueprint; changing it signs everyone out |
| `APP_CORS_ALLOWED_ORIGINS` | `https://diacare-one.vercel.app` | Comma separated, no trailing slash |
| `DB_POOL_SIZE` | `5` | |
| `DEMO_ADMIN_PASSWORD` / `DEMO_DOCTOR_PASSWORD` / `DEMO_PATIENT_PASSWORD` | `<private>` | Used only when the database is empty |
| `DEMO_SEED_ENABLED` | `true` | Optional; `false` skips demo data |
| `PORT` | set by Render | Locally the API uses 8085 |

Vercel → project → Settings → Environment Variables (Production and Preview):

| Variable | Value |
|----------|-------|
| `VITE_API_URL` | `https://diacare-api.onrender.com/api/v1` |

Vercel project settings: Root Directory `DiaCareFrontend`, Framework Vite, build
`npm run build`, output `dist`. `DiaCareFrontend/vercel.json` rewrites every path to
`index.html` so deep links such as `/patient/dashboard` work.

## How a clean database is initialised

There are no migration files. On start-up against an empty database:

1. Hibernate (`spring.jpa.hibernate.ddl-auto=update`) creates every table, key and constraint.
2. `DataSeeder` sees no users and inserts the fictional demo data: one admin, two doctors,
   two patients, their profiles, prescriptions, appointments, 30 days of glucose readings,
   health metrics and notifications. Passwords come from the `DEMO_*_PASSWORD` variables.

Restarting never reseeds, because the seeder only runs when the `users` table is empty.

## Redeploying

- **API:** push to the branch the Render Blueprint follows (Render auto-deploys), or Render →
  `diacare-api` → Manual Deploy → Deploy latest commit. Changing an environment variable
  also redeploys.
- **Frontend:** push to `main` (Vercel builds production), or Vercel → Deployments →
  Redeploy. Changing `VITE_API_URL` needs a redeploy because Vite bakes it in at build time.
- **Render Blueprint:** `render.yaml` at the repository root describes the service.

## Backup and restore

Use PostgreSQL 18 client tools (`pg_dump`, `pg_restore`, `psql`) and Neon's **direct**
host (the endpoint without `-pooler`). Keep dumps out of Git.

```bash
# Backup (custom format)
PGPASSWORD='<neon password>' pg_dump -h <endpoint>.<region>.aws.neon.tech -U <neon role> \
  -d <db> --no-owner --no-privileges -Fc -f diacare-neon.dump

# Restore into a separate local database. Neon's dump carries internal
# "SET (pg_attver=...)" column options that plain PostgreSQL rejects, so convert
# the dump to SQL, drop those lines and load it with psql.
createdb -h localhost -p 5432 -U postgres diacare_restore
pg_restore --no-owner --no-privileges -f - diacare-neon.dump \
  | grep -v "SET (pg_attver=" \
  | psql -h localhost -p 5432 -U postgres -d diacare_restore -v ON_ERROR_STOP=1

# Run the API against the restored copy
SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/diacare_restore \
SPRING_DATASOURCE_USERNAME=postgres SPRING_DATASOURCE_PASSWORD='<local password>' \
JWT_SECRET='<32+ chars>' java -jar DiaCare/target/diacare-0.0.1-SNAPSHOT.jar
```

Neon Free also keeps 6 hours of history, so recent mistakes can be undone from the
Neon console (Branches → Restore).
